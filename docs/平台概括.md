# 企业级 AI Agent 平台概括

> 日期：2026-07-29  
> 状态：基础方案，待产品边界确认

## 一句话定义

这是一个面向企业应用开发者的 Agent 构建与运行平台：统一管理模型、提示词、知识库、工具、MCP、记忆和工作流，并为 Agent 的每次运行提供权限、审批、追踪、评测和成本控制。

## 为什么做

分享内容指出，AI 应用岗位的核心已经从“调用一次模型 API”转向“把大模型能力做成稳定业务系统”。平台要解决的正是工程落地问题：

- 多模型接入、降级、限流与成本核算；
- Agent 的状态、步骤、重试、中断和恢复；
- RAG 文档处理、混合检索、重排与引用；
- 工具注册、MCP 接入、权限边界与人工审批；
- 短期/长期/知识记忆；
- 全链路 Trace、离线评测、线上反馈和回归；
- 多租户、角色权限、密钥管理和审计。

## 目标用户

1. AI 应用工程师：快速组合并调试 Agent。
2. 企业研发团队：把 Agent 嵌入现有业务系统。
3. 平台管理员：管理模型、工具、配额、安全与审计。
4. 评测/运营人员：用数据集和指标判断版本是否可发布。

## 首期范围

首期建议做成一个“控制台 + API + Agent Runtime”的最小闭环：

1. 创建 Agent，配置模型和系统提示词；
2. 注册一个 HTTP 工具或 MCP Server；
3. 创建知识库并上传文档；
4. 在 Playground 发起流式对话；
5. 查看一次运行的步骤、工具参数、引用、延迟和 Token；
6. 对高风险工具设置人工审批；
7. 保存测试集，对 Agent 版本运行回归评测；
8. 发布版本，通过 API 调用。

## 暂不纳入首期

- 自研基础模型、训练平台、RLHF、CUDA 优化；
- 完整低代码 BPM 平台；
- 开放式第三方插件市场；
- 复杂多地域容灾和大规模 Kubernetes 运维；
- 无约束的自主多 Agent 群体。

## 成功标准

- 一个开发者可在 30 分钟内创建并运行首个 Agent；
- 每次运行均可追踪模型、工具、知识引用、延迟、Token 和错误；
- 高风险工具未经授权或审批不能执行；
- Agent 新版本可以通过固定数据集回归后再发布；
- API 服务和 Web 控制台可独立部署与扩容。

## 当前假设

- 首期是 Web 平台，不做原生移动端；
- 后端以 Python/FastAPI 为主，Agent 编排优先采用 LangGraph；
- 前端采用 Vue 3 + TypeScript；
- PostgreSQL 存业务数据，Redis 存临时状态/队列，Qdrant 存向量，MinIO 存原始文件；
- 平台优先服务单组织私有部署，再演进为 SaaS 多租户；
- 默认所有有副作用的工具都需要显式权限，高风险动作支持人工审批。

这些假设决定后续实现方向，如需更换技术栈或优先做“智能任务指挥 Agent”，应先修改技术说明再进入功能实现。
