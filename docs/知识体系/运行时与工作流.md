# Agent Runtime（智能体运行时）与 Workflow（工作流）系统学习指南

> 上位导航：[AI Agent 知识体系](README.md)

> LLM 决定“可能做什么”，运行时保证“怎样安全地做、失败后怎样继续”。生产 Agent 的可靠性主要来自显式状态、持久执行、幂等、重试、补偿和可验证终止，而不是模型永不出错。

## 0. 运行时负责什么

- 驱动模型—工具循环；
- 保存 State（状态）与 Checkpoint（检查点）；
- 调度节点、并行任务和队列；
- 执行超时、重试、取消和预算；
- 处理中断、审批和恢复；
- 实施权限与 Guardrail（护栏）；
- 记录 Trace（执行轨迹）、指标和审计；
- 验证成功、失败和降级结果。

## 1. Workflow、State Machine 与 DAG

### 1.1 Workflow（工作流）

用代码定义业务步骤、转移条件和错误处理。适合已知流程和强治理场景。

### 1.2 State Machine（状态机）

系统状态与合法转移显式化：

```text
created → running → waiting_approval → running → succeeded
                 ↘ retrying      ↘ failed
```

非法转移应被拒绝，例如已经取消的任务不能被旧 Worker（工作者）重新标记为成功。

### 1.3 DAG（有向无环图）

DAG 表达节点依赖并允许并行，例如先并行检索三个来源，再汇总。动态 Agent 可能产生循环，因此底层不一定是纯 DAG；但单次计划或批处理经常可以表示为 DAG。

### 1.4 Agentic Node（智能体节点）

工作流中的某个节点内部允许模型动态调用工具。这样既保留外层确定性，又让局部具备灵活推理能力。

## 2. State 设计

State 建议分区：

- Business State（业务状态）：订单、文档、用户确认等领域数据。
- Control State（控制状态）：当前节点、尝试次数、截止时间、等待原因。
- Agent State（智能体状态）：目标、计划、证据引用、待解决问题。
- Security Context（安全上下文）：主体、租户、权限、授权版本。
- Budget State（预算状态）：Token、费用、工具次数和剩余时间。

状态字段应有明确所有者与更新规则。不要让多个并发节点自由覆盖同一个大 JSON。

## 3. Checkpoint 与 Durable Execution

Durable Execution（持久执行）意味着进程崩溃、服务重启或人工等待后，任务仍能从已提交状态继续。

Checkpoint 应包含：

- 状态版本与当前节点；
- 已提交的工具调用及结果引用；
- 等待中的审批或外部事件；
- 重试次数与下一次执行时间；
- Prompt、工具、模型和策略版本；
- 幂等键、Lease（租约）与必要的安全上下文。

LangGraph 等图运行时会在步骤边界持久化状态，使历史回放、更新和恢复成为可能。选框架时要验证真实语义，而不是只看是否存在 `checkpoint` API。

## 4. 队列、Lease 与 Heartbeat

长任务通常由队列调度：

- Worker 获取任务并持有有期限的 Lease；
- 定期 Heartbeat（心跳）续租；
- Worker 崩溃后租约到期，任务可重新分配；
- 通过版本号或 Fencing Token（隔离令牌）阻止旧 Worker 提交结果。

“至少一次投递”意味着任务可能重复执行，所以工具副作用必须幂等。若声称 Exactly-once（恰好一次），要说明它通常依赖业务幂等、去重与事务边界组合，而不是消息系统魔法。

## 5. Retry、Backoff 与 Circuit Breaker

### 5.1 重试矩阵

| 错误 | 是否重试 | 做法 |
|---|---|---|
| 网络抖动、临时 5xx | 是 | 指数退避 + 随机抖动 + 上限 |
| 限流 | 是 | 尊重 Retry-After，降低并发 |
| 参数校验失败 | 否/修正后再试 | 返回结构化字段错误 |
| 权限拒绝 | 否 | 停止或请求授权 |
| 业务冲突 | 重新读取后决定 | 基于最新状态重规划 |
| 结果未知的写操作 | 不能直接重放 | 先按幂等键查询 |

### 5.2 Circuit Breaker（熔断器）

依赖持续失败时临时停止请求，避免资源耗尽和级联故障。配合 Bulkhead（舱壁隔离）限制单个工具、租户或任务占满所有并发。

## 6. Saga 与补偿

跨系统长事务示例：

```text
创建预订 → 扣款 → 发券
```

若发券失败：可以重试发券；若最终失败，按业务定义退款并取消预订。Saga 记录每一步结果和对应补偿。关键认识：补偿不是数据库回滚，可能不可逆、失败或需要人工判断。

## 7. Human-in-the-loop 与 Interrupt

Interrupt（中断）用于等待审批、补充信息或外部事件：

1. 在安全边界前持久化状态；
2. 生成结构化审批请求，展示动作、参数、影响与证据；
3. 释放 Worker，不长期占用线程；
4. 收到决定后校验审批者身份与时效；
5. 恢复时重新读取关键业务状态；
6. 执行或拒绝，并记录审计。

审批的是具体动作与参数，不是模糊的“允许 Agent 继续”。参数变化后应重新审批。

## 8. 并发与状态冲突

### 8.1 常见问题

- 两个节点同时写同一字段，后写覆盖前写；
- 汇总节点在部分分支未完成时启动；
- 重试任务与原任务同时运行；
- 用户取消后旧 Worker 仍提交；
- 多 Agent 重复执行相同工具。

### 8.2 治理方法

- 每个字段或子资源定义单一 Owner（所有者）；
- Optimistic Concurrency Control（乐观并发控制）和版本检查；
- 分支结果写入各自命名空间，汇总节点只读；
- Barrier（屏障）或 Quorum（法定数量）控制聚合；
- Lease、Fencing Token 和取消标志阻止陈旧写入；
- 副作用使用全局幂等键。

## 9. 预算与背压

预算至少包括：

- 最大模型调用和工具调用次数；
- 输入、输出与总 Token；
- 单任务费用；
- 端到端 Deadline；
- 并行分支数和队列容量；
- 单租户和全局速率限制。

Backpressure（背压）意味着下游变慢时，上游降低生产速度、排队或拒绝低优先级任务，而不是无限扩张并发。

## 10. 版本与可恢复性

长任务恢复时，代码、Prompt、模型和工具 Schema 可能已经更新。Checkpoint 要记录版本，并制定：

- 继续用旧版本执行；
- 将旧状态迁移到新 Schema；
- 在安全节点重新开始；
- 无法兼容时转人工。

没有版本化的持久化工作流，会在发布后出现难以复现的“幽灵任务”。

## 11. 常见失败与排错

### 11.1 进程重启后任务重复执行

检查 Checkpoint 提交点、队列投递语义、幂等键、Lease 与工具执行记录。

### 11.2 一直卡在 running

检查 Worker 心跳、Deadline、未处理 Future（异步结果）、依赖超时、取消传播和状态机非法转移。

### 11.3 并行后结果丢失

检查分支是否覆盖同一字段、聚合 Barrier 是否正确、状态版本冲突是否被吞掉、部分失败策略是否明确。

### 11.4 重试使系统雪崩

检查是否所有层同时重试、是否有指数退避和抖动、是否尊重限流、是否有熔断、并发限制和全局截止时间。

### 11.5 恢复后权限失效

身份和授权可能在等待期间变化。恢复时重新授权，不应永久信任 Checkpoint 中的旧许可。

## 12. 面试重点

### 12.1 Agent 为什么需要持久化运行时？

答题要点：模型调用和外部工具会失败，长任务会跨进程、部署和人工等待。显式 State 与 Checkpoint 才能恢复、去重、审计和控制副作用。

### 12.2 Checkpoint 应该放在哪里？

答题要点：步骤边界、副作用前后、人工等待前、长阶段完成后和上下文压缩处。需要与业务提交语义协调，避免“工具成功但状态未记”造成重复执行。

### 12.3 怎样处理多步骤事务？

答题要点：本地事务保证单服务原子性；跨服务用 Saga 记录步骤和补偿；工具幂等；不可逆动作前审批；补偿失败进入重试或人工队列。

### 12.4 并行 Agent 如何避免状态冲突？

答题要点：按子任务隔离状态和单写者所有权，使用版本控制、分支命名空间与聚合屏障；共享副作用通过幂等和仲裁器串行化。

### 12.5 “Exactly-once” 怎样实现？

答题要点：网络系统难以凭传输本身保证端到端恰好一次。生产上使用至少一次投递 + 业务幂等键 + 去重记录 + 事务性状态提交，得到等效的一次业务效果。

## 13. 术语速查

| 英文 | 中文 | 含义 |
|---|---|---|
| Durable Execution | 持久执行 | 故障或等待后仍能恢复任务 |
| State Machine | 状态机 | 状态与合法转移的形式化表示 |
| DAG | 有向无环图 | 表示节点依赖和并行关系的图 |
| Lease | 租约 | Worker 在有限时间内拥有任务处理权 |
| Heartbeat | 心跳 | 证明执行者仍存活并续租 |
| Fencing Token | 隔离令牌 | 阻止过期执行者提交状态 |
| Circuit Breaker | 熔断器 | 依赖持续失败时暂时停止调用 |
| Backpressure | 背压 | 下游饱和时限制上游流量 |
| Saga | 长事务 | 用步骤记录和补偿管理跨服务事务 |
