# LLM（大语言模型）基础：面向 Agent 工程

> 上位导航：[AI Agent 知识体系](README.md)

> 本文不追求从数学上完整推导 Transformer（变换器），而是解释 Agent 工程师必须理解的模型能力、调用参数、输出约束、失败边界和选型方法。

## 0. 先建立全局认识

LLM 的核心能力是：根据当前输入上下文预测后续 Token（词元）。指令遵循、推理、规划和工具选择，都是这种能力在训练与推理阶段表现出的高级行为，不意味着模型内部存在可靠的数据库、权限系统或事务引擎。

Agent 系统必须补上模型缺少的部分：

- 用 RAG（检索增强生成）补充新知识和私有事实。
- 用 Tool（工具）查询实时状态或产生真实动作。
- 用 Runtime（运行时）管理状态、循环、超时、恢复和终止。
- 用 Guardrail（护栏）与 Policy Engine（策略引擎）实施安全限制。
- 用 Evaluation（评测）衡量概率系统，而不是只看几个演示案例。

## 1. Token、上下文窗口与注意力

### 1.1 Token（词元）

模型不是直接按“字”或“单词”工作，而是将文本切成 Token。中英文、代码、特殊字符的 Token 比例不同，所以不能简单用字符数估算成本和上下文长度。

输入 Token 通常包括：

- System / Developer Instructions（系统 / 开发者指令）
- 用户消息与历史对话
- 工具定义与工具结果
- RAG 召回内容与 Memory
- 中间推理可见部分和结构化数据

输出 Token 包括自然语言答案、结构化参数和某些模型的 Reasoning Tokens（推理词元）。

### 1.2 Context Window（上下文窗口）

上下文窗口是一次推理能处理的输入与输出总容量上限。窗口更大不等于所有位置的信息都能被同等利用：长上下文会增加成本与延迟，噪声还会稀释关键证据。

工程结论：上下文工程的目标不是“尽量塞满”，而是以最小的高信号上下文支持当前决策。

### 1.3 Attention（注意力）

Self-Attention（自注意力）让每个 Token 根据其他 Token 计算相关性，从而建模长距离依赖。工程上要理解两点：

1. 计算资源和上下文长度相关，长输入通常更贵、更慢。
2. 模型对上下文位置和噪声敏感，关键规则应清晰、集中、避免互相冲突。

## 2. 训练、知识与推理边界

### 2.1 Pretraining（预训练）

预训练让模型学习语言、世界知识和通用模式，但参数知识存在截止时间、不透明且无法逐条精确更新。

### 2.2 Instruction Tuning（指令微调）与 Alignment（对齐）

指令微调与偏好优化让模型更会遵循要求、拒绝不当任务并以可用形式回答。但“更愿意遵循”不等于“保证遵循”，因此高风险规则必须由代码执行。

### 2.3 Inference（推理）

推理阶段模型只基于当前上下文和参数生成结果。模型不会自动知道：

- 数据库刚刚发生了什么变化；
- 当前用户拥有哪些真实权限；
- 某个工具是否调用成功；
- 上一轮没有放入上下文的信息；
- 自己的陈述是否真的有证据。

这些都要通过外部系统显式提供或验证。

## 3. 常见生成参数

| 参数 | 作用 | Agent 工程建议 |
|---|---|---|
| `temperature` | 调节采样随机性 | 工具参数、分类和事实任务通常偏低；创意任务可提高 |
| `top_p` | 限制累计概率候选集 | 通常与 temperature 选一个主要调节，不盲目同时大改 |
| `max_output_tokens` | 限制最大输出 | 同时作为成本与失控保护，不应承担终止全部 Agent 的职责 |
| `stop` | 命中序列后停止 | 适合稳定协议；结构化输出优先使用原生 Schema（模式）约束 |
| `seed` | 尝试提高采样可复现性 | 不能把它当跨版本、跨硬件的绝对确定性保证 |

低温度也不能消除幻觉；它主要降低采样随机性，不能补回缺失事实或修复错误上下文。

## 4. Structured Output 与 Tool Calling

### 4.1 为什么需要结构化输出

自然语言适合给人阅读，不适合直接驱动程序。结构化输出通过 JSON Schema（JSON 模式）约束字段、类型和枚举，使结果更容易验证和执行。

生产链路应是：

```text
模型生成参数
  → Schema Validation（模式校验）
  → Semantic Validation（语义校验）
  → Authorization（授权校验）
  → 执行工具
```

即使 Schema 合法，`amount: 1000000` 或 `recipient: attacker` 仍可能在业务上不合法，所以不能省略语义与授权校验。

### 4.2 Tool Calling 的本质

模型通常只是生成“建议调用哪个工具及其参数”。真正的工具执行由应用或服务完成，再把结果作为 Observation（观察）返回模型。模型的工具调用输出不是可信命令，更不是授权凭证。

## 5. Model Routing（模型路由）

不是所有步骤都需要最强模型。常见分层：

- 小模型：意图分类、字段抽取、简单重写、低风险格式化。
- 主模型：复杂推理、工具选择、综合生成。
- 专用模型：Embedding（嵌入）、Rerank（重排序）、语音、视觉、审核。
- 高能力模型：复杂规划、困难恢复、最终审校；按条件升级。

路由依据应包括质量、延迟、成本、上下文长度、结构化输出能力、工具能力和安全要求。路由器自身也要评测，否则省下模型成本却增加误路由成本。

## 6. LLM 在 Agent 中的常见失败

### 6.1 Hallucination（幻觉）

模型生成语言上合理但事实错误或证据不足的内容。治理要分层：提供可靠证据、要求引用、核验关键声明、允许拒答，而不是只追加“不要幻觉”。

### 6.2 Instruction Conflict（指令冲突）

系统规则、用户要求、检索文档、工具结果可能互相冲突。应用必须建立可信边界和优先级：不可信文档中的文字只能作为数据，不能升级为系统指令。

### 6.3 Tool Misuse（工具误用）

模型选错工具、填错参数、重复调用或在无需调用时调用。应通过工具描述、缩小候选集、参数校验、幂等键、风险审批和评测治理。

### 6.4 Loop（循环）

模型反复执行无进展步骤。应同时设置最大步数、时间/Token/费用预算、重复动作检测、进度判定和安全降级。

### 6.5 Non-determinism（非确定性）

相同输入可能产生不同路径。测试不能只断言完整文本相等，应优先验证最终环境状态、关键约束、工具副作用和允许的轨迹范围。

## 7. 模型选型方法

先定义代表真实流量的评测集，再比较：

- Task Success Rate（任务成功率）
- Tool Selection / Argument Accuracy（工具选择 / 参数准确率）
- Groundedness（有据性）与事实正确率
- P50 / P95 延迟
- 单任务输入、输出、工具和重试总成本
- 安全拒绝、越权与 Prompt Injection（提示词注入）防护结果
- 长上下文与多轮任务中的稳定性

不要仅用公开 Benchmark（基准测试）排名替代业务评测。Agent 的最终效果是模型、Prompt、工具、上下文、运行时和环境共同作用的结果。

## 8. 系统化排错

| 现象 | 优先检查 | 常见根因 |
|---|---|---|
| 回答事实错误 | 模型实际收到的上下文与证据 | 缺少 RAG、召回错误、证据冲突 |
| 工具调用失败 | 工具定义、参数、返回值与 Trace | Schema 模糊、参数缺失、工具错误未结构化 |
| 同题结果波动大 | 采样参数、路由、外部数据 | 随机性、检索漂移、并发竞态 |
| 变慢变贵 | Token 分布、工具次数、重试次数 | 历史无限增长、工具过多、循环 |
| 拒绝正常请求 | 规则命中记录、分类器与 Prompt | 护栏过严、语义分类误判、上下文污染 |

排错原则：先看完整输入、输出、工具调用和状态变化，再修改 Prompt。很多“模型问题”实际上是上下文、工具契约或运行时问题。

## 9. 面试重点

### 9.1 LLM 为什么会幻觉？低温度能解决吗？

答题要点：LLM 优化的是下一个 Token 的条件概率，不是事实数据库查询；缺知识、错误上下文和任务歧义都会产生幻觉。低温度只减少随机性，不能保证真实性。需要 RAG、工具查询、声明级核验、引用和拒答机制共同治理。

### 9.2 Function Calling（函数调用）是否保证执行正确？

答题要点：只提高输出结构的可解析性。系统仍需做 Schema、业务语义、权限和风险校验；执行端要有超时、幂等、重试、审计和补偿。

### 9.3 长上下文是否可以替代 RAG？

答题要点：不能一概替代。长上下文适合一次性小规模语料和全局理解；RAG 适合大规模、频繁更新、带权限和需要引用的知识。长上下文仍有成本、延迟、噪声与位置效应。

### 9.4 怎样选择大小模型？

答题要点：基于任务级评测做路由；简单分类与抽取用小模型，复杂规划与恢复用强模型，必要时升级。比较任务成功率、延迟、总成本和失败代价，而不是只看单次调用价格。

### 9.5 为什么 Agent 测试不能只比较最终文本？

答题要点：路径具有非确定性，多个轨迹可能都正确；应核验最终环境状态、工具副作用、权限约束、关键步骤和成本预算，并对开放质量使用经人工校准的模型评分器。

## 10. 术语速查

| 英文 | 中文 | 含义 |
|---|---|---|
| Token | 词元 | 模型处理文本的基本单位 |
| Context Window | 上下文窗口 | 单次推理可容纳的输入输出容量 |
| Inference | 推理 | 使用训练完成的模型生成结果 |
| Structured Output | 结构化输出 | 按指定结构生成可解析结果 |
| Function Calling | 函数调用 | 模型生成函数名与参数的机制 |
| Sampling | 采样 | 从概率分布中选择后续 Token |
| Hallucination | 幻觉 | 生成无事实依据或错误内容 |
| Model Routing | 模型路由 | 按任务选择模型或配置 |
