# RAG 高频面试题

> 返回：[AI Agent 面试题库](README.md)｜配套知识：[RAG 系统学习指南](../知识体系/RAG.md)

## 1. 生产级 RAG 的完整链路是什么？ `★★★★★`

### 标准回答

离线链路包括数据接入、解析清洗、结构化分块、元数据与权限、Embedding（向量化）、关键词/向量索引和版本发布。在线链路包括查询理解、权限过滤、Sparse / Dense Retrieval（稀疏 / 密集检索）、Fusion（融合）、Rerank（重排序）、Context Packing（上下文组装）、生成、引用与声明核验。

生产系统还要有证据充分性、拒答、离线评测、线上 Trace、反馈闭环、增量更新和回滚。RAG 不是“向量库 + LLM”，任何环节都可能决定最终质量。

## 2. 如何设计 Chunking（分块）？过大或过小有什么问题？ `★★★★★`

### 标准回答

优先按文档结构和语义边界切分，再设置最大 Token 和必要 Overlap（重叠）。技术文档按标题/段落/步骤，FAQ 按问答对，代码按类和函数，表格保留表名、表头和行列关系。Chunk 要携带标题路径、文档 ID、版本、页码和权限。

过大时混合多个主题、向量语义被稀释、重排和生成成本增加；过小时语义断裂、索引膨胀且需要召回多个碎片。参数必须按文档类型，用 Recall@K、答案质量、延迟与成本共同评测。

## 3. 标题与正文被切开导致召回错误，如何定位与修复？ `★★★★★`

### 标准回答

从 Bad Case 回溯原文，标出解析与切分边界，检查标题层级是否在解析阶段丢失；再统计正确正文是否进入 Top K，以及只命中标题的候选比例。

根治方案是结构感知切分：在同一标题层级内再按长度或语义切；每块注入 Header Path（标题路径）并保留 Parent ID。还可采用 Parent-Child Retrieval（父子块检索）：小块精确召回，返回父块或邻近块供生成。简单增加 Overlap 只能缓解，不能修复解析丢失。

## 4. BM25 与向量检索有什么区别？为什么使用 Hybrid Search？ `★★★★★`

### 标准回答

BM25 基于词项匹配与词频，擅长错误码、编号、专有名词和精确关键词；向量检索擅长同义表达、口语化和语义近似，但可能漏掉罕见字符串或召回主题相似却事实不支持的内容。

Hybrid Search（混合检索）并行运行两类检索，通过 RRF（倒数排名融合）或经过校准的加权融合互补。对于编号型查询可提高关键词权重，但仍保留语义通道。最终用业务评测决定权重，不能直接相加不同尺度的原始分数。

## 5. HNSW 和 IVF 是什么？怎样选择向量索引？ `★★★★☆`

### 标准回答

HNSW（分层可导航小世界图）构建多层近邻图，查询速度和召回通常较好，但索引内存较高、构建和更新有成本。IVF（倒排文件索引）先把向量聚类到多个分区，查询只扫描部分分区；可结合 PQ（乘积量化）降低内存，但需要训练并调节 `nprobe` 等参数。

小规模可直接精确搜索；高召回、内存充足、在线查询常选 HNSW；超大规模或内存敏感可考虑 IVF/PQ。应在真实向量分布上比较 Recall、P95 延迟、内存、构建时间、更新方式和过滤性能。

## 6. Reranker 解决什么问题？为什么不能修复漏召回？ `★★★★★`

### 标准回答

初始检索用 Bi-Encoder（双塔编码器）或 BM25 快速扩大候选覆盖；Cross-Encoder Reranker（交叉编码重排序器）同时读取 Query 和候选片段，判断更细粒度的相关性或证据支持程度，提高前几名精度。

Reranker 只能重排候选集，正确文档未被召回时无能为力。因此分别评估候选 Recall@K，以及重排后的 MRR、NDCG、Precision@K。重排也会增加延迟，并受输入截断和领域差异影响。

## 7. Query Rewriting、Multi-Query、HyDE 和 Query Decomposition 有什么区别？ `★★★★☆`

### 标准回答

- Query Rewriting（查询改写）：将口语、上下文依赖问题改成适合检索的独立查询。
- Multi-Query（多查询扩展）：生成多个表达，从不同角度召回后融合。
- HyDE（假设文档嵌入）：先生成可能答案或文档，再用其向量检索真实材料。
- Query Decomposition（查询分解）：把多跳复杂问题拆成多个子问题，分步检索。

它们都会增加调用、延迟和查询漂移风险。改写必须保留实体、时间和否定条件；简单问题不应默认启动复杂策略。

## 8. 知识库有正确内容但回答错误，怎样系统排查？ `★★★★★`

### 标准回答

保存完整 Trace，然后沿数据流定位第一个错误点：

1. 原文是否存在且版本正确。
2. 解析是否漏页、乱码、OCR 或表格错位。
3. 正确内容是否形成完整 Chunk 并进入正确索引。
4. 是否被权限/元数据过滤误删。
5. 是否进入初始 Top K。
6. 是否被融合或 Reranker 淘汰。
7. 是否因 Token 预算未进入最终 Prompt。
8. 证据完整进入后模型是否忠实使用。

使用 Oracle Context（理想上下文）对照：人工提供正确证据。若仍失败，查生成、Prompt 或模型；若成功，查检索与组装。

## 9. 如何判断证据不足并正确拒答？ `★★★★★`

### 标准回答

相似度高不等于足够回答。检索后需要 Answerability / Evidence Sufficiency（可回答性 / 证据充分性）判断：结构化问题检查必要字段，自由文本可用规则、NLI、受约束模型或多者组合判断证据是否覆盖结论。

不足时明确说明缺少什么，允许补充信息或转人工。生成后把答案拆成原子 Claim（声明），验证是否被引用支持。阈值要使用同时包含“有答案”和“无答案”的评测集校准，高风险场景更重视降低错误回答。

## 10. RAG 幻觉有哪些类型？怎样全链路治理？ `★★★★★`

### 标准回答

一类是检索事实问题：文档错误、过期、冲突或不相关；另一类是生成忠实性问题：证据正确但答案没有遵循证据。

治理覆盖数据版本和来源、结构化分块、混合检索、重排、上下文去重、证据充分性、引用、拒答、声明级核验与高风险人工复核。低 Temperature 和“只基于上下文”Prompt 只能辅助，不能替代证据与验证机制。

## 11. 如何自动检测 RAG 答案幻觉？ `★★★★☆`

### 标准回答

有证据时优先做声明级核验：拆分原子事实，对每条输出 Supported、Contradicted 或 No Evidence，并检查引用是否真实支持对应声明。NLI 可做低成本筛查，复杂样本使用 LLM-as-a-Judge，关键结论用规则或人工。

黑盒自一致性只能反映模型不确定性；一致答案也可能稳定地错误。白盒 Token 概率、语义熵或隐藏层探针需要按模型和版本重新校准。检测器本身要评估 Precision、Recall、误杀和漏检。

## 12. 如何建立可信的 RAG 评测集？ `★★★★★`

### 标准回答

从真实查询、线上失败、用户反馈和专家需求取样，每题保存标准答案、支持证据、可接受范围、数据版本、权限和是否应拒答。覆盖关键词、语义、多跳、表格、冲突版本、无答案、越权、长上下文与对抗问题。

分开评估检索 Recall@K、MRR/NDCG，生成正确性、Faithfulness（忠实度）、引用和拒答，以及系统延迟与成本。开发集用于调参，独立测试集最终比较；固定模型和数据版本，报告切片、样本量和不确定性，再用线上小流量验证。

## 13. 传统 RAG、GraphRAG 与 Agentic RAG 怎样选择？ `★★★★☆`

### 标准回答

传统 RAG 适合答案集中在少量片段的事实问答，成本最低。GraphRAG 适合实体关系、多跳和跨文档全局总结，但增加实体消歧、图构建、更新和评测成本。Agentic RAG 让 Agent 根据中间结果选择数据源、改写、分解和停止，适合路径不可预先固定的复杂检索，同时增加循环、成本和安全风险。

生产中可分层路由：普通问题走传统 RAG，关系型问题走图检索，复杂开放任务再用 Agent 编排。是否升级以评测收益为准。

## 14. 企业 RAG 如何做权限控制？为什么不能先召回再隐藏？ `★★★★★`

### 标准回答

文档和 Chunk 写入租户、文档、ACL、版本和敏感级别。查询时服务端根据认证身份生成不可被模型修改的过滤条件，在关键词和向量检索阶段完成授权过滤；高敏租户可物理隔离索引。

先召回再隐藏会让无权限内容占据 Top K，更严重的是它已进入缓存、日志、应用内存或模型上下文，构成泄露。权限变更和删除也必须同步更新索引、缓存与派生数据。

## 15. 知识持续变化时如何增量更新并保证一致性？ `★★★★☆`

### 标准回答

为源文档保存 ID、版本、更新时间和 Content Hash。监听内容事件或 CDC（变更数据捕获），只重建变化文档；块哈希未变可复用 Embedding。删除和撤权必须走同一链路。

新版本先写入独立命名空间，完成解析、索引和校验后原子切换 Active Version，再清理旧版本，避免空窗和混合版本。任务要幂等、可重试，有 DLQ（死信队列）、版本积压监控和回滚能力。

## 16. RAG 延迟较高，如何优化而不明显降低质量？ `★★★★☆`

### 标准回答

先分解查询改写、Embedding、稀疏/向量召回、融合、重排和生成的 P95，定位真正瓶颈。可并行独立检索通道；缓存查询 Embedding 和带权限/版本的只读结果；控制候选数量；采用轻量粗排 + 精排；缩短上下文；批量请求和连接复用。

任何减少 Top K、关闭 Reranker 或换小模型的优化都要用切片评测验证 Recall、答案质量和拒答没有显著退化。最终比较每个成功回答的总成本和尾延迟。
